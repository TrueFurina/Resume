# 项目介绍与技术方案

> 物理学科智能排课选课智能体系统 —— 调课辅助最小闭环

---

## 一、项目介绍

### 1.1 一句话介绍

**物理实验调课辅助系统**：教师输入自然语言调课请求，系统结合实验安排表、学生课表和教师课表，自动筛出所有无冲突的可用时段，供教师选择、管理员审批。

### 1.2 解决的问题

高校物理实验教学存在多约束排课问题：

- 多学院、多班级并行上课（不同培养方案）
- 多教师、多实验室、设备资源受限
- 教师临时调课需人工核对三重冲突：
  1. 目标时段教室是否被占用
  2. 学生该时段是否有其他课程
  3. 调课教师自身该时段是否有课

传统做法靠人肉查表、问学委，无法高效解决**跨班、跨教师、跨实验室的连锁冲突**。

### 1.3 核心价值

| 价值 | 说明 |
|------|------|
| 效率提升 | 一次查询秒级返回所有可用时段，替代人工查表 |
| 冲突规避 | 三重检查确保推荐时段无硬冲突 |
| 零学习成本 | 自然语言输入，无需指定具体时段 |
| 低侵入 | 只输出建议，不修改教务系统，管理员保留最终决定权 |

### 1.4 目标用户

| 用户 | 场景 |
|------|------|
| 实验教师 | 临时调课、补课协调 |
| 教学管理人员 | 审批调课、评估调课可行性 |

## 二、技术方案

### 2.1 技术栈

| 层 | 技术 | 选型理由 |
|----|------|---------|
| 后端框架 | Python FastAPI | 快速开发、自动生成 API 文档 |
| Excel 解析 | openpyxl | 读取实验安排表 |
| PDF 参考 | pypdf / PyMuPDF | 解析学生课表 PDF |
| 前端 | React 18 + Vite 5 | 快速构建对话式界面 |
| 样式 | Tailwind CSS 3 | 快速布局 |
| 数据存储 | 内存 + Excel 文件 | 最小闭环无需数据库 |

### 2.2 系统架构

```
┌─────────────────────────────────────┐
│           前端 (React)              │
│   调课对话界面 / 数据加载 / 状态栏   │
└──────────────┬──────────────────────┘
               │ HTTP (JSON)
┌──────────────▼──────────────────────┐
│        FastAPI 后端                 │
│  ┌───────────────┐                 │
│  │  RescheduleAgent │               │
│  │  自然语言解析    │               │
│  │  三重冲突筛选    │               │
│  └───────┬───────┘                 │
│  ┌───────▼───────┐                 │
│  │ ScheduleDatabase│               │
│  │  (实验安排表)   │               │
│  └───────┬───────┘                 │
│  ┌───────▼───────┐                 │
│  │ StudentSchedule│               │
│  │  (学生课表)    │               │
│  └───────────────┘                 │
└─────────────────────────────────────┘
```

### 2.3 核心模块

#### 模块一：实验安排表解析（ScheduleDatabase）

- 位置：`backend/app/utils/excel_parser.py`
- 读取"大学物理实验安排表 (周)"工作表
- 关键设计：**时间格式归一化**
  - Excel 中时间有 12 种写法（`13:30-15:45`、`567`、`91011`、`15:50-18:05`……）
  - 通过 `TIME_SLOT_NORMALIZE` 映射统一为节次标记（`567`/`678`/`91011`/`78`）
  - 归一化是冲突检查正确性的前提（否则比对不上）

#### 模块二：学生课表服务（StudentSchedule）

- 位置：`backend/app/agent/student_schedule.py` + `utils/student_data.py`
- 数据结构：课程名、星期、节次、周次表达式
- 支持周次解析：`1-15周`、`4-6周(双)`、`1-6周,8-10周,12-17周`
- 节次映射：`1-2节→上午(不排实验)`、`5-7节→567`、`7-8节→78`、`9-11节→91011`

#### 模块三：调课智能体（RescheduleAgent）

- 位置：`backend/app/agent/reschedule_agent.py`
- 自然语言解析：
  - 「第六周的课上不了，调到下周」→ 源周6，目标周7
  - 「调到第5周」→ 目标周5
  - 「调到第十周」→ 支持中文数字
  - 「我是吴琳」→ 识别教师身份
- 三重冲突筛选：
  1. **教室占用**：同周同天同时段同教室是否已被排
  2. **学生课表**：学生该时段是否有课
  3. **教师时间**：调课教师自身该时段是否有课

### 2.4 数据流

```
实验安排表.xlsx ──→ openpyxl 解析 ──→ ScheduleDatabase（内存索引）
                                        │
学生课表数据 ───────→ StudentSchedule ──┤
                                        ▼
教师输入 ──→ parse_request ──→ find_available_slots（三重筛选）
                                        │
                                        ▼
                            可用时段列表（星期×时间×教室）
```

### 2.5 API 设计

| 方法 | 路径 | 功能 | 请求体 |
|------|------|------|--------|
| POST | `/api/reschedule/upload` | 上传实验安排表 | multipart file |
| POST | `/api/reschedule/load-default` | 加载默认数据 | - |
| POST | `/api/reschedule/chat` | 调课咨询 | `{"message": "..."}` |
| GET | `/api/reschedule/status` | 系统状态 | - |
| GET | `/health` | 健康检查 | - |

**chat 接口响应示例：**

```json
{
  "success": true,
  "message": "📋 第7周可用时段：\n周一：\n  567 · A410\n...\n共 62 个空闲时段",
  "data": {
    "target_week": 7,
    "available_slots": [
      {"weekday": "周一", "time_slot": "567", "room": "A410"}
    ],
    "total": 62
  }
}
```

### 2.6 前端界面

- 单页应用（`frontend/src/App.tsx`）
- 结构：顶部状态栏 + 中间对话区 + 底部输入框
- 功能：加载默认数据、上传 Excel、对话式调课请求
- 配置：`vite.config.ts` 中 `host: '0.0.0.0'`（避免 IPv6 监听导致 localhost 拒绝连接）+ `/api` 代理到后端

## 五、已知限制与后续方向

### 已知限制

| 限制 | 说明 |
|------|------|
| 单学生课表 | 目前内置张敏杰课表，多学生需扩展 |
| 教师识别 | 基于"我是XXX"/姓名关键词，非语义理解 |
| 时间段范围 | 仅工作日（周一~五）下午/晚上 |
| 无持久化 | 调课申请未入库，重启即失 |

### 后续方向

1. 多学生课表批量导入（Excel）
2. 调课申请单持久化 + 审批记录
3. 管理员审批界面
4. 冲突影响范围可视化（"这一改会影响谁"）
5. 接入 LLM 增强意图理解
6. 部署上线
