# 调课模块验收标准与迭代计划 v1.1

> 物理学科智能排课选课智能体系统 · 调课模块
> 日期：2026-08-15 ｜ 状态：评审反馈后修订

## 一、验收标准

### 1.1 功能验收用例

| 用例ID | 场景 | 操作步骤 | 预期结果 |
|--------|------|---------|---------|
| TC-01 | 教师身份选择 | 1. 打开系统 2. 点击教师卡片"吴琳" | 进入吴琳的调课首页，顶部显示"当前教师：吴琳" |
| TC-02 | 我的课程列表 | 吴琳身份下查看课程 | 展示吴琳名下全部课程卡片，标注【可调/不可调】 |
| TC-03 | 不可调原因展示 | 查看不可调课程卡片 | 卡片标注原因（如"实验轮次固定"） |
| TC-04 | 模板调课 | 选课程 → 下拉选周次/星期/时段 → 查询 | 返回可用时段列表 |
| TC-05 | 原因标注 | 查看筛选结果 | 每个不可用时段附排除原因（教室/学生/教师） |
| TC-06 | 可用时段选择 | 勾选可用时段 → 提交 | 生成调课申请单，状态"待审批" |
| TC-07 | 管理员审批 | 管理员登录 → 查看待审批 → 同意/驳回 | 同意提示去教务系统改；驳回填原因反馈教师 |
| TC-08 | 自然语言调课 | 输入"我是吴琳，第六周周四的课调到下周" | 正确解析 → 返回第7周可用时段 |
| TC-09 | 多轮追问 | 输入"我想调课"（信息不全） | 系统追问：调哪门课？调到什么时间？ |
| TC-10 | 身份切换 | 顶部返回身份选择 → 选另一位教师 | 课程列表刷新为新教师 |

### 1.2 冲突筛选准确性验收

| 用例ID | 场景 | 验证点 |
|--------|------|--------|
| TC-11 | 教室冲突 | 目标时段教室被占用 → 该时段标"不可用（教室占用）" |
| TC-12 | 学生课表冲突 | 学生该时段有课 → 标"不可用（学生有课）" |
| TC-13 | 教师自身冲突 | 教师该时段已有课 → 标"不可用（教师冲突）" |
| TC-14 | 正确性抽查 | 随机抽 20 个"可用"时段人工核对无冲突 | 通过率 100% |

### 1.3 评审意见覆盖度检查

| 评审意见 | 对应功能 | 覆盖 |
|---------|---------|------|
| 用户一进来是懵的，不知有哪些课 | F2 我的课程列表 | ✅ |
| 系统应知道用户是谁 | F1 身份选择 + 顶部身份显示 | ✅ |
| 火车票改签式交互 | F3 模板表单（先展示课程再选时间） | ✅ |
| 信息透传不足，不知为什么不可选 | F4 筛选结果原因标注 | ✅ |
| 纯自由文本缺信息 | F3 模板为主 + F5 多轮追问 | ✅ |
| 权限身份问题 | F6 教师/管理员角色 + 审批流 | ✅ |
| 缺少引导 | 页面1→2→3→4 步骤清晰 | ✅ |

### 1.4 非功能验收

| 项 | 标准 |
|----|------|
| 冲突筛选响应 | < 2秒（1000条数据） |
| 大模型依赖 | 规则引擎兜底，不依赖外部模型也能完成调课 |
| 数据来源 | 全部来自真实实验安排表 + 学生课表 |

## 三、演示脚本（下次汇报用）

```
[1] 身份选择：演示教师卡片，点击"吴琳"
[2] 我的课程：展示吴琳全部课程（可调/不可调标注）
[3] 模板调课：选"大学物理实验C" → 目标第5周 → 查询
[4] 结果展示：可用时段（绿）+ 不可用时段（灰，附原因）
[5] 提交申请 → 状态"待审批"
[6] 管理员审批：同意/驳回 → 反馈
[7] （备选）自然语言：输入一句话调课 → 成功解析
```

**演示话术要点（应对评审提问）：**
- "系统知道用户是谁，先展示其名下全部课程" —— 回应"用户懵"批评
- "每个不可用时段都有原因" —— 回应"信息透传不足"
- "参考火车票改签：先看票，再改签" —— 回应王铮导师建议
- "模板为主 + 自然语言为辅" —— 回应"单轮对话缺陷"
- "审批闭环，系统不改教务" —— 回应"权限身份"与边界问题
