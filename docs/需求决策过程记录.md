# 需求决策过程记录

> 物理学科智能排课选课智能体系统
> 记录时间：2026-07-26 ~ 2026-08-02

---

## 一、背景：这个项目差点被砍掉

项目最初（PRD v0.3）规划了三大功能：

| 规划功能 | 优先级 |
|---------|--------|
| 规则知识库管理（上传 PDF/Word → AI 抽取规则 → 人工审核） | P0 |
| AI 教学咨询（自然语言问答选课/排课问题） | P0 |
| 排课冲突分析（上传 Excel → 检测冲突 → 生成报告） | P0 |

**但产品负责人在深入思考后，一度认为"根本不知道搞这个项目的意义"。**

---

## 二、需求验证过程：逐一推翻假设

### 2.1 从"目标用户"开始质疑

| 原假设 | 实际情况（学生亲历验证） | 结论 |
|--------|----------------------|------|
| 学生需要选课咨询 | 大物实验是公共必修课，理工科强制必选，**不存在"选不了课"** | ❌ 砍掉学生端 |
| 教师需要系统内调课 | 教师调课**统一走教务系统**管理 | ❌ 砍掉调课流程系统 |
| 管理员角色存在 | 作为学生接触到的只有老师，**不清楚是否存在专职管理员** | ⚠️ 存疑 |
| 排课很痛 | 学校有一张实验安排表，"每年微调就够" | ⚠️ 部分存疑 |

### 2.2 调研：论文验证真实痛点

通过网络调研多篇高校实验教学论文，验证了以下结论：

**① 教务系统确实管不了实验排课**

> "由于各种原因，**很少有分组实验课出现在排课系统中**。由课程主讲教师主导的实验排课不得不依旧停留在传统的、低效的人工模式。" ——《基于师生协同的实验课教学管理新模式》（安徽工业大学，2024）

**② 实验排课是"二次分配"问题**

> "实验课排课本质上是在不影响学校课表的前提下，对教师、学生和实验室时间进行二次分配的问题。一处调整可能影响多个教学班。" ——北京邮电大学论文

**③ 调课连锁反应真实存在**

> "一节课的调整，连带触发了3-5个学科、多位老师的时间冲突。"
> "微调一节课常触发多位教师的时间冲突，本质是高密度约束下的约束传播现象。" ——排课系统实践分析

### 2.3 竞品/替代方案分析：为什么现有工具不够

| 候选功能 | 现有替代方案 | 结论 |
|---------|------------|------|
| 签到扫码 | **学习通**已支持 | ❌ 不重复造轮子 |
| 实验报告拍照上传 | 物理实验**要求手写纸质报告** | ❌ 不符合教学要求 |
| 成绩统计 | **Excel** 已够用 | ❌ 无需系统 |
| 调课冲突查询 | **问学委**（学生视角） | ⚠️ 但只能查一个班，无法跨班跨教师 |

**关键洞察：问学委只解决"一个班有没有课"，排课管理员的痛点是多班、多教师、多实验室的连锁冲突。**

## 三、产品方向收敛

### 3.1 从"系统思维"到"用户思维"

**最初的思路（系统思维）：**
> 老师指定"调到周四下午3点" → 系统检测冲突 → 报错/通过

**收敛后的思路（用户思维）：**
> 老师说"第六周的课上不了，调到下周" → 系统**筛掉所有有冲突的时段** → 剩下的自然就是可选的 → 老师挑选即可

这一步简化非常关键：**用户不需要知道具体目标时段，系统直接给可用选项。**

### 3.2 最小闭环确定

```
教师输入自然语言调课请求
    ↓
系统解析：目标周次 + 教师身份
    ↓
三重冲突筛选：教室占用 + 学生课表 + 教师自身时间
    ↓
输出所有可用时段（星期 × 时间段 × 教室）
    ↓
教师选择 → 管理员审批 → 手动修改教务系统
```

**边界：系统只给分析和建议，不直接改教务系统。**

## 四、被砍掉的需求清单（及理由）

| 被砍功能 | 砍掉理由 |
|---------|---------|
| 学生选课端 | 公共必修课强制必选，无选课需求 |
| 签到扫码 | 学习通已覆盖 |
| 实验报告批改 | 手写纸质是教学要求 |
| 规则知识库 | 需求未验证，且项目聚焦调课闭环 |
| AI 教学咨询 | 学生端已砍，咨询场景收窄 |
| 自动排课生成 | 超出"调课辅助"定位，PRD 也明确本期不做 |
| 教务系统对接 | 技术依赖学校接口，暂不协调 |
| 多方案优化比较 | 超出 MVP 范围 |

---

## 五、留下的核心价值

**一句话定位：为物理实验教学管理人员和教师，提供一个"输入自然语言 → 自动筛出无冲突可用时段"的调课辅助工具。**

论文和真实数据都支持：实验排课确实存在多约束协调的痛点，而现有工具（Excel、问学委）无法高效解决跨班跨教师的连锁冲突。**但解决方式不是做一个庞大的排课系统，而是做一个聚焦的、单问题的辅助工具。**
