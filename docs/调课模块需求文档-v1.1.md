# 调课模块需求文档 v1.1

> 物理学科智能排课选课智能体系统 · 调课模块（MVP 迭代版）
> 版本：v1.1 ｜ 日期：2026-08-15 ｜ 状态：评审反馈后修订

---

## 0. 版本变更说明（v1.0 → v1.1）

本版本基于中期验收评审会（胡锐锋、王铮、任成森等评委意见）修订，核心变化：

| 评审意见 | v1.0 现状 | v1.1 改进 |
|---------|----------|-----------|
| 用户一进系统"两眼空白"，不知道有哪些课可调 | 只有自由文本对话框 | 增加**调课首页课程列表**，展示当前教师全部课程 |
| 系统应知道用户是谁，展示其名下课程 | 无身份概念，管理员模式 | 增加**教师身份选择**（可视化选择是哪位老师） |
| 参考火车票改签交互 | 让用户输入一句话 | 改为**选课程 → 看可用时段** 的两步式交互 |
| 信息透传不足：不知道哪些时间可选、为什么 | 只输出可用时段 | 输出时段时**标注排除原因** |
| 纯自由文本缺信息，用户不知补什么 | 只支持一句话 | 增加**模板表单**快捷调课 |
| 缺少教师/管理员角色与审批流 | 无权限体系 | 增加**角色区分 + 管理员审批** |

## 1. 项目背景

### 1.1 项目定位

物理学科智能排课选课智能体系统的**调课子模块**（最小 MVP）。核心解决：教师临时调课时，多班级、多教室、多实验室资源冲突的自动化筛选问题。

### 1.2 业务痛点（评审会确认）

- 实验排课是"二次分配"问题：一处调整可能引发多班、多教师、多教室连锁冲突
- 教务系统管不了实验排课，靠人工协调，效率低
- 现有调课流程对用户不透明：用户不知道有哪些课可调、哪些时间可用、为什么不可用

### 1.3 核心原则

1. **系统知道用户是谁**：登录后系统展示该教师名下全部课程，用户无需回忆/输入
2. **先展示，后操作**：参考火车票改签——先看"我有哪些票"，再选"可改签时间"
3. **信息透传**：每个不可选时段都要说明原因（被谁占用/约束）
4. **辅助不替代**：系统只输出建议，最终由管理员审批后在教务系统操作

## 2. 目标用户与角色

| 角色 | 说明 | 核心场景 |
|------|------|---------|
| **实验教师**（核心） | 物理实验课授课教师（吴琳、林珠云等13人） | 发起调课、查看可用时段、提交申请 |
| **教学管理员**（次要） | 负责审批调课、管理课表 | 审批教师调课申请、查看冲突报告 |

## 3. 功能需求

### 3.1 教师身份选择（F1）——新增

**场景**：教师打开系统，系统不知道"我是谁"。

**需求**：
- 系统自动加载教师列表（从实验安排表提取的 13 位教师）
- 以**可视化卡片/列表**形式展示所有教师，让用户点选自己的身份
- 选中后系统进入该教师的调课工作台

**验收标准**：
- 页面展示全部教师姓名（含职称/院系信息更好）
- 点击某位教师后，进入该教师的调课首页
- 身份选择可随时切换（返回按钮）

### 3.2 调课首页 · 我的课程列表（F2）——新增

**场景**：教师进入调课后，应该立刻知道"我有哪些课、哪些能调"。

**需求**：以卡片列表展示当前教师名下**全部课程**，每条课程标注：

| 信息 | 说明 |
|------|------|
| 课程名称 | 如"大学物理实验C" |
| 教学班级 | 如"2024级信息安全+海洋资源与环境" |
| 原上课时间 | 周几 + 时段（如 周四 13:30-15:45） |
| 上课教室 | 如 A504 |
| 周次范围 | 如 第4-10周 |
| **可调状态** | ✅ 可调 / ❌ 不可调 |
| **不可调原因** | 如"该课程为固定实验轮次，不可单独调整" |

**验收标准**：
- 展示该教师名下全部课程（吴琳 → 约25条排课记录，合并为课程卡片）
- 每张卡片明确标注【可调/不可调】状态
- 不可调的卡片说明原因

### 3.3 调课发起 · 模板表单（F3）——新增（替代纯自由文本）

**场景**：参考火车票改签，用户不输入自然语言，而是**选择**。

**需求**：用户选择"我要调哪门课"后，系统提供模板表单：

```
调课申请单
┌─────────────────────────────────────┐
│ 课程：大学物理实验C（周四 13:30-15:45 @ A504）│
│ 原时间：第4周 周四 567                  │
│ 目标周次：[第5周 ▼]  ← 下拉选择         │
│ 目标星期：[周四 ▼]   ← 下拉选择         │
│ 目标时段：[567 ▼]    ← 下拉选择         │
│ 备注：（选填）                          │
│ [查询可用时段]                          │
└─────────────────────────────────────┘
```

**同时保留自然语言输入作为进阶方式**（多轮对话信息补全，见 3.5）。

**验收标准**：
- 模板表单字段齐全，可下拉选择
- 提交后调用冲突筛选接口
- 无自由文本输入也能完成调课

### 3.4 可用时段筛选 · 原因标注（F4）——改进

**场景**：系统筛出可用时段，但用户不知道**为什么其他时段不可用**。

**需求**：筛选结果分两部分展示：

**① 可用时段（绿色）**：可直接选择的时段列表
```
✅ 周一 567 (13:30-15:45) · A410
✅ 周二 567 (13:30-15:45) · A410
```

**② 不可用时段（灰色，附原因）**：列出被排除的时段及原因
```
❌ 周三 567 · A410 —— 教室已被占用（应用化学1班 声速测量）
❌ 周四 567 · A410 —— 学生有课（大学物理实验C）
❌ 周五 567 · A410 —— 教师该时段已有课（应用化学1班）
```

**验收标准**：
- 每个不可用时段的排除原因明确（教室占用/学生有课/教师冲突）
- 原因可追溯到具体排课记录
- 可用时段按 星期×时段 分组展示

### 3.5 自然语言调课（F5）——保留，作为进阶

**场景**：熟练用户可直接说"我是吴琳，第六周周四的课调到下周"。

**需求**：
- 保留自然语言输入入口
- 增加**多轮对话信息补全**：系统识别缺失信息（缺哪门课/缺目标周次），主动追问
- 支持快捷模板提示（如"试试输入：把第6周周四的课调到下周"）

**验收标准**：
- 一句话能完成调课（已有）
- 信息不全时系统主动追问缺失项（新增）

### 3.6 管理员审批流（F6）——新增

**场景**：教师提交调课申请后，需管理员审批。

**需求**：
- 教师提交申请 → 生成调课申请单（含课程、原时间、目标时间、原因）
- 管理员审批列表：查看待审批申请、同意/驳回
- 同意后提示"请在教务系统中完成修改"（系统不直接改教务）
- 驳回时管理员可填写原因，系统反馈给教师

**验收标准**：
- 教师能提交申请并看到状态（待审批/已通过/已驳回）
- 管理员能审批并填写意见
- 审批状态流转正确

## 4. 数据设计（新增部分）

### 4.1 教师身份数据

- 来源：实验安排表教师列（已提取 13 人）
- 字段：姓名、职称、院系（从安排表提取，可补充）

### 4.2 课程卡片数据

- 来源：实验安排表中该教师的所有排课记录
- 按（课程名 + 教学班）合并为课程卡片
- 可调状态规则：
  - 固定实验轮次（如实验项目序列）→ 标记为"受轮次约束，调整需管理员评估"
  - 常规课程 → 可调

### 4.3 冲突原因标注数据

- 筛选时记录每个被排除时段的**原因类型**：
  - `classroom_busy`：教室占用（具体课程）
  - `student_busy`：学生有课（具体课程）
  - `teacher_busy`：教师冲突（具体课程）
- 响应结构示例：

```json
{
  "available": [
    {"weekday": "周一", "time_slot": "567", "room": "A410"}
  ],
  "excluded": [
    {
      "weekday": "周三", "time_slot": "567", "room": "A410",
      "reason_type": "classroom_busy",
      "reason": "教室已被占用（应用化学1班 声速测量）"
    },
    {
      "weekday": "周四", "time_slot": "567", "room": "A410",
      "reason_type": "student_busy",
      "reason": "学生有课（大学物理实验C）"
    }
  ]
}
```

## 5. 非功能需求

| 项 | 要求 |
|----|------|
| 响应时间 | 冲突筛选 < 2秒（1000条数据） |
| 可用性 | 调课流程不依赖外部大模型（规则引擎兜底） |
| 数据准确性 | 冲突检测不漏报（评审关注点） |
| 可解释性 | 每个筛选结果可追溯到原因（评审核心要求） |
